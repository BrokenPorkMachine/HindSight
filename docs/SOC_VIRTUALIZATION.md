# Apple SoC Virtualization Kit

## Scope

HindSight virtualizes the parts that macOS Hypervisor.framework can execute directly and emulates the parts that are Apple-SoC-specific. On an Apple Silicon Mac, compatible AArch64 guest instruction execution can use HVF. A12/T2 device fabrics and SEP are not magically exposed by HVF, so they are modeled behind a deterministic VMKit-style device graph.

## Layers

1. **CPU backend** — Hypervisor.framework ARM64 vCPU, guest RAM, execution/exit loop (first milestone creates the VM/vCPU; execution scheduling is next).
2. **Memory fabric** — guest physical address map, RAM, ROM, MMIO windows, shared coprocessor windows.
3. **Interrupt model** — Apple AIC-oriented interrupt routing model.
4. **DART/IOMMU model** — DMA translation contract for emulated devices.
5. **Device models** — UART, timers, SPI/I2C stubs, ANS/NVMe research model, mailbox/doorbell devices.
6. **Coprocessor model** — SEP/T2-oriented mailbox state machines and shared-memory queues. SEP execution is emulation, not HVF passthrough.
7. **Firmware adapters** — user-supplied, legally obtained firmware/images; identity and signing material are never generated by HindSight.

## Profiles

### A12-class Research VM
Uses an HVF ARM64 vCPU plus emulated AIC, DART, UART/timer, ANS/NVMe, and SEP-mailbox surfaces. It is intended for driver/boot-flow/firmware research, not cycle-accurate iPhone reproduction.

### T2 Research VM
Provides an ARM64 research VM with T2-oriented mailbox/storage/USB service topology. It does not emulate Apple device secrets or provide a substitute for a physical T2.

### SEP Lab
Focuses on SEP-style mailbox, shared-memory, interrupt-doorbell, and secure-storage mock contracts. No UID/GID keys, attestation identity, or hardware-backed cryptography is synthesized.
