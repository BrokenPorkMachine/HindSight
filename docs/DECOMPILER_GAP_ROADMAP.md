# Decompiler and Reverse Engineering Feature Roadmap

Implementation follows the [Chimera master list of completion](CHIMERA_COMPLETION_ROADMAP.md), which maps every remaining item here to dependencies and acceptance gates and prioritizes source recreation.

This checklist compares HindSight's current analysis path with capabilities documented by Hopper, Ghidra, IDA, and Binary Ninja. It focuses on features that can improve evidence-backed static analysis in HindSight's current Apple binary workflow. The commercial tools' output is not treated as ground truth: each recovered name, type, and structure should retain its evidence and uncertainty.

## Current baseline

- [x] ARM64 instruction semantics with bounded constant and provenance tracking.
- [x] Basic-block construction and bounded control-flow propagation.
- [x] Address-bearing ARM64 lifted instruction/function records consumed directly by CFG and value analysis.
- [x] C-like ARM64 output with dyld, Objective-C, C, CoreFoundation, and supported C++ symbol/signature recovery.
- [x] Pseudocode accessible from the Binary Workspace and application navigation.
- [x] Conservative conditional-return structuring for one proven branch pattern.
- [ ] General source-variable, stack-local, and type recovery.
- [ ] General C control-flow structuring, switch recovery, and architecture-independent decompilation.

## P0 — Make current pseudocode dependable and useful

### Recently completed (from development plan)
- [x] Bounded ARM64 call-argument/return-register provenance; source-level types remain explicit.
- [x] PC-relative literal loads and ADR/ADRP with unslid provenance.
- [x] Bounded cross-basic-block value propagation (merge at joins, calls/returns/indirect clear).
- [x] Conditional-select, conditional comparisons, comparisons as no-reg-effect markers, system-register reads/writes, and atomic/exclusive operations in bounded semantic preview.
- [x] SIMD/FP scaffolding (V-register tracking, MOVI.2D, FMov, and scalar FP tracking markers).

- [x] **Normalize function boundaries.** One aligned, deduplicated boundary set from Mach-O function starts, executable nlist symbols, validated Objective-C IMPs, exports, validated `__unwind_info` index/page entries, and in-range direct `BL` targets drives CFG, function, pseudocode, unified-symbol, and static-symbolication ranges. Reports share boundary evidence and confidence; call-target-only entries remain candidates. The decompilation corpus verifies the function, resolver, and symbolication range sets match.
- [x] **Build a first-class per-function CFG.** Preserve block edges, predecessors, successors, reachability, dominators, loop backedges, and lifted branch conditions as structured data in the ARM64 semantics pass.
- [x] **Prune proven conditional CFG edges.** Block-local constants and known NZCV results remove impossible branch edges before reachability and dominator analysis; unknown or unsupported operations retain both paths.
- [x] **Add an initial lifted IR.** Address-bearing typed ARM64 instruction records and a function container now feed CFG construction, propagation, and rendering without reparsing formatted statements.
- [x] **Add a shared IR core.** ARM64 now maps common assignments, integer arithmetic/logical operations, simple memory accesses, calls, returns, and branches into architecture-neutral records. The CFG consumes shared control-flow operations; unsupported forms remain explicitly target-specific.
- [x] **Route the shared IR through analysis and rendering.** Common assignments, arithmetic/logic, supported memory operations, calls, returns, and branches now update value flow and render from the shared records.
- [x] **Preserve load/store writeback.** Pre-indexed and post-indexed immediate scalar and pair memory operations now record base-register updates in shared IR and apply them in architectural order. Pair forms with a writeback/base-register overlap remain target-specific because their architectural result is constrained or unpredictable.
- [~] **Complete shared IR coverage.** Vector three-same integer arithmetic (`ADD`/`SUB`/`MUL` across `B`/`H`/`S`/`D`/`Q` lanes) now uses shared IR with bounded constant folding; half-precision scalar FP add, subtract, multiply, divide, minimum/maximum (`FMAX`/`FMIN`/`FMAXNM`/`FMINNM`), comparisons, and conditional select now use shared IR with a `Half` precision variant (manual f16→f32 bit conversion for constant materialization); vector floating-point three-same arithmetic (`FADD`/`FSUB`/`FMUL`/`FDIV`/`FMAX`/`FMIN`/`FMAXNM`/`FMINNM` across `4s`/`2d` lanes) now uses shared IR with bounded constant folding for `Q=1` forms; vector reciprocal estimate (`FRECPE`/`FRSQRTE` for both `Q=1` (Quad) and `Q=0` (Double) lanes) now uses shared IR; vector FP compare (`FCMEQ`/`FCMGT`/`FCMGE`/`FCMLT`/`FCMLE` for `4s`/`2d` lanes) now uses shared IR with canonical operand ordering; half-precision vector three-same arithmetic (`FADD`/`FSUB`/`FMUL`/`FDIV`/`FMAX`/`FMIN`/`FMAXNM`/`FMINNM` across `.4h`/`.8h` lanes) now uses shared IR; scalar reciprocal exponent (`FRECPX` for single/double) now uses shared IR; Load/SimdLoad rendering now attempts string/integer reconstruction from `LC_DATA_IN_CODE` ranges when address provenance is known; remaining vector reciprocal-exponent forms, and remaining target-specific instructions still need explicit shared semantics or documented fallback rules. *(in progress — claimed; do not start independently)* ARM64 compare/test and conditional compare operations have explicit shared records; known NZCV values can pass through known flag-preserving moves, shifts, and memory operations to resolve a branch or select. Proven scalar FP constants now produce AArch64 FCMP NZCV flags, including unordered NaN, and known conditions prune branches; FP writes and generic SIMD operations invalidate tracked vector constants. Scalar single/double `FMOV` immediate materialization and register copies preserve low-lane values and provenance in shared IR. Flag-setting arithmetic and unknown operations invalidate the state. Shifted arithmetic, shifts, multiply families, logical-register operations, move-wide keep, division, one-source operations, bitfield operations, extended add/subtract, sign/zero extension, pair load/store instructions, system markers, discarded zero-register results, atomic/exclusive single-register accesses, scalar single/double FP add, subtract, multiply, divide, minimum/maximum (`FMAX`/`FMIN`/`FMAXNM`/`FMINNM` rendered as shared call expressions), unary operations (`FABS`/`FNEG`/`FSQRT`/`FRINT*` now lifted into shared IR instead of the target-specific fallback), register/zero comparisons, single-to-double/double-to-single precision conversion, signed/unsigned 32/64-bit integer/FP conversions, fixed-point conversions with encoded fractional scaling, and scalar `S`/`D` memory accesses using unsigned, unscaled, pre-indexed, post-indexed, and supported register-offset addressing now have shared records. Lane-wise vector bitwise data processing (`AND`/`BIC`/`ORR`/`ORN`/`EOR`/`BSL`/`BIT`/`BIF` and the `MOV` alias) now uses shared IR, preserves unrelated GPR/FP state, and folds full-width proven constants with bounded provenance; 64-bit partial writes remain unknown. Vector arithmetic beyond bitwise operations, half-precision FP arithmetic, remaining reciprocal-exponent forms, and remaining target-specific instructions still need explicit shared semantics or documented fallback rules; vector memory access itself now uses shared records. Exclusive pair loads/stores (LDXP/STXP/LDAXP/STLXP) and pair compare-and-swap (CASP) now render as modeled markers. General-register and scalar FP unprivileged loads/stores (`LDTR`/`STTR`) use the same shared IR as their unscaled forms, since the address expression is identical and only the translation regime differs. Fixed-point float-to-integer output records truncation and leaves out-of-range architecture behavior marked unresolved.
- [x] **Lift scalar FP literal loads.** Single and double PC-relative `LDR` literal forms now use shared float-load IR and retain their resolved address provenance; vector-Q literals remain target-specific.
- [x] **Lift integer SIMD lane extracts with explicit GPR effects.** All 82 legal `UMOV`/`MOV` and `SMOV` size/lane/width forms use shared extraction records and exact sign/zero-extension results with bounded provenance. They replace only the destination GPR identity, never masquerade as source-variable copies, and preserve NZCV. Apple-assembled fixtures plus 42,640 native comparisons qualify normal EL0 non-streaming lane results. Reserved/unmodeled SIMD/FP words remain opaque barriers; trap/SME and general vector arithmetic semantics remain open.
- [x] **Lift scalar fused multiply-add group.** `FMADD`/`FMSUB`/`FNMADD`/`FNMSUB` (both single and double precision) now map to `IrOperation::ScalarFloatMultiplyAdd` with provenance-carrying registers, and render as `fmadd`/`fmsub`/`fnmadd`/`fnmsub` call expressions.
- [x] **Lift scalar FP conditional select.** Single/double `FCSEL` now uses shared IR and preserves GP registers, unrelated FP registers, and NZCV. Proven block-local conditions propagate selected FP bit patterns with source and comparison provenance, bounded to eight instruction sites; unknown or over-budget proof invalidates the destination. AL and NV normalize to always-select-first. Half precision, FPCR modes, and vector lanes remain unresolved.
- [x] **Lift SIMD memory access without discarding general-purpose value flow.** The Advanced SIMD load/store single-register group now has shared records for one lane of `B`/`H`/`S`/`D` and for the full `Q` register, across unsigned-offset, unscaled, pre-indexed, post-indexed, unprivileged, register-offset, and PC-relative literal addressing; register-offset forms scale by the 128-bit access size when `S` is set, and `B`/`H` name an integer memory view without claiming half-precision arithmetic. `LDP`/`STP` now decode from the architectural `opc`/`L`/width table instead of treating `opc` as the direction, which covers signed offset, pre-index, and post-index over general-purpose and `S`/`D`/`Q` registers plus `LDPSW`. These instructions invalidate only their own V-register destinations, so a `ldr q0, [x0]` no longer discards unrelated proven constants as an all-GPR barrier. Pre-indexed pairs render both halves relative to the updated base, and the second half of every pair is addressed at the first half's offset plus the access size. Non-temporal `LDNP`/`STNP` pairs share these memory effects while preserving their no-writeback behavior; reserved opcodes, lane-wise vector arithmetic, and the load/store *multiple structures* group remain on the conservative fallback.
- [x] **Lift scalar reciprocal estimates and refinement steps.** Single/double `FRECPE`, `FRSQRTE`, `FRECPS`, and `FRSQRTS` now render as named shared IR calls. Results remain unknown with explicit estimate-accuracy/FPCR/FPSR limitations; GP registers, unrelated FP values, and NZCV are preserved. Half precision, vector, and integer forms retain their prior fallback; scalar `FRECPX` now renders as `frecpx` with unresolved FPCR/FPSR behavior.
- [x] **Add bounded GPR SSA evidence.** The IR preview now exposes deterministic, instruction-addressed definitions/uses and live phi merges with predecessor inputs. W/X views share physical identities; SP writeback, indexed addressing, atomic status, read-modify-write operands, unreachable blocks, and loop headers are modeled. Calls, data, and target-specific instructions replace prior GPR identities with explicit unknowns. Analysis is limited to the existing 128-instruction function preview and SSA output to 4,000 bytes per function. These are machine values; source names/types, FP/flags/memory SSA, implicit ABI arguments, and pseudocode variable replacement remain.
- [x] **Replace text-derived parameter-name flow with bounded shared-effect identities.** Decoded instructions now determine copies, CFG joins/backedges, paired writes, source widths and frame spills/restores; input/output names are distinct and conflict/limit reasons remain visible. Six Apple-assembled functions, 1,560 original-native result checks and the unchanged decompilation corpus qualify this bounded scope. See [source-parameter identity scope](AARCH64_SOURCE_VARIABLES.md); this does not complete general source-variable recovery or reconstructed-source equivalence.
- [ ] **Replace machine-register temporaries with recovered variables.** Supported parameter identities now survive same-bank copies, agreeing CFG paths and intact modeled frame spills, including paired/FP accesses. Known source widths constrain register views; redefinitions, narrowing, conflicting paths, aliases, calls and unknown effects invalidate identities. SP-relative slot labels still require proven unchanged SP; restored parameter identity is not a general stack-local declaration. Canonical GPR SSA is exposed separately in the IR preview. General source locals, lifetimes/coalescing, typed expression AST, memory/FP/flags SSA and analyst edits remain.
- [ ] **Structure common control flow.** Proven straight-line `if`/`else` diamonds now render as nested blocks only when both arms reach one explicit join and no branch enters an arm interior. Straight-line natural loops with one conditional backedge render as `do`/`while`; header-tested loops render as `while` only when their exit immediately follows one explicit backedge and the body is linear. Bounded jump tables render as candidate switches, while unstructured direct and indirect branches state why they remain as gotos. Nested regions and broader CFG structuring remain.
- [ ] **Improve call-site reconstruction.** Direct ARM64 BL pseudocode maps known prototypes to AAPCS64 parameter registers and uses entry-register evidence for candidate argument arity when a prototype is unavailable. When an indirect call's target register resolves to a constant address with a recovered function signature, pseudocode now uses that signature while marking the dispatch as indirect; bare data symbols cannot supply an indirect-call prototype. Proven x0-x7 and scalar s0-s7/d0-d7 constants retain instruction provenance, including scalar immediates and values transferred between GP and FP registers or copied between FP registers, with FP values interpreted using the recovered parameter type. Proven floating-point call arguments are recovered from immediate materialization, GP/FP transfers, and FP register copies. Objective-C and C call reconstruction improved with ABI-aware parameter mapping. Unknown target or arity, FP/aggregate stack contents, broader stack-argument resolution, and call side effects remain unresolved; stack parameters carry a slot index and proven scalar stores can supply values. Imported prototypes and Objective-C method encodings supply supported arity and names.
- [ ] **Keep source mapping in the UI.** Address-bearing pseudocode statements in the Binary Workspace navigate using only the renderer's leading instruction address; embedded call targets, constants, and memory addresses cannot hijack the source mapping. Assembly and pseudocode share the selected instruction, highlight it, and scroll it into view in each pane. Assembly and pseudocode navigation are synchronized with aligned source mapping. Pseudocode source mapping is measured in the decompilation corpus. Statements synthesized from multiple instructions, expression-level variable-use highlighting, and source ranges remain.

## P1 — Recover types and Apple runtime semantics

- [x] **Join target property/ivar layouts to bounded AArch64 pseudocode.** Structured captured-binary layouts produce class/property declarations, retain custom accessors and backing ivars, and refine generic object accessor types only when method encodings agree. A bounded shared-IR receiver analysis follows copies, intact frame spills and agreeing CFG paths to render compatible named member accesses with metadata/offset-slot provenance. Runtime-offset variables retain symbolic identity. Native-oracle `-O0/-O2` fixtures and malformed-layout/alias/barrier tests qualify this scope; general receiver/type propagation and arbitrary layouts remain open.

- [x] **Establish native Darwin catalog tooling.** The isolated libobjc/dyld helper records image UUID/ownership, classes/metaclasses, selectors/method encodings/IMPs, properties, ivars and supported native type layouts. Apple Clang imports C declarations with SDK/target provenance and exports source-hash-bound prototypes into worker pseudocode; real `-O0/-O2` fixtures qualify the path. Native catalog-to-target joins, arbitrary layouts and UI integration remain open. See [Darwin native evidence](DARWIN_NATIVE_EVIDENCE.md).

- [x] **Preserve argument casts and protocol declarations as evidence.** Recovered prototypes now interpret proven GP argument constants at the formal type width and signedness, render explicit scalar/pointer casts, retain raw register/provenance evidence, and withhold noncanonical boolean interpretation. Runtime encodings that conflict with Foundation catalog ABI types retain their decoded declaration. Validated protocol objects supply scoped required/optional class/instance declarations and ABI bindings without creating IMPs, dispatch targets or function boundaries. Protocol inheritance/conformance constraints, arbitrary type libraries and most stack-passed values remain open.

- [x] **Recover proven scalar outgoing stack arguments.** Direct and resolved indirect calls substitute prototype-typed constants from bounded SP-relative integer stores when the source value and formal width are proven. Intervening calls, possible aliases, opaque instructions, and SP changes invalidate older stores. FP and aggregate stack contents remain unresolved.

- [x] **Establish Apple ARM64 prototype ABI rules.** Exact scalar/opaque-pointer types, independent GP/FP register banks, naturally packed stack arguments, `CFRange`/`NSRange` integer aggregates, and `CGPoint`/`CGSize`/`CGRect` FP aggregates now determine supported parameter and return locations. Exact known Objective-C aggregate encodings retain their layout evidence; callback/block/array parameters remain pointers. FP bank overflow never consumes GP registers, `void *` returns remain values, and anonymous variadic arguments stay unresolved. Unknown aggregates and ambiguous C++ receivers withhold subsequent location claims. Real Mach-O `-O0`/`-O2` fixtures verify metadata-to-pseudocode behavior; arbitrary layouts, FP/aggregate stack values, debug types, Swift ABI and cross-function constraint solving remain. See [prototype ABI scope](MACHO_PROTOTYPE_ABI.md).

- [ ] **Recover function signatures.** Exact ABI prototypes cover selected Foundation/CoreFoundation, C runtime, libdispatch, and Objective-C runtime APIs; validated Objective-C method encodings, supported Itanium mangling, and ARM64 entry-register candidates add further evidence. Pseudocode maps Objective-C self/_cmd and typed selector parameters to ABI registers, maps C/C++ prototype parameters across the integer and FP register banks, and labels unsupported incoming values as candidates. Direct calls show formal-to-register bindings and retain provenance for proven constant substitutions. Objective-C and C ABI pseudocode improved with better parameter mapping and call reconstruction. Swift function signatures, debug-info ingestion, complete per-parameter confidence, and broader caller/callee constraint solving remain.
- [ ] **Infer stack locals and aggregate layouts.** The report groups decoded SP-relative accesses by signed offset, observed width, read/write role, and example sites. Pseudocode uses the same slot labels only when SP stability is proven; otherwise it keeps machine expressions and explains that SP stability was not proven. General pointer-relative grouping, variable lifetimes, aggregate field inference, and analyst edits remain.
- [ ] **Add a project type library.** Import and apply SDK headers, user C declarations, structs, enums, typedefs, and function prototypes. Initially support Foundation, CoreFoundation, libSystem, and Objective-C runtime APIs.
- [ ] **Model Objective-C dispatch and objects.** Validated class and method metadata now handles 72-byte 64-bit `class_ro_t` records and relative method lists; selector-specific `__objc_stubs` resolve their validated `__objc_selrefs` selector and render message sends. Receiver and argument types remain unresolved, as do other stub shapes, receiver class resolution, property patterns, and complete class/metaclass/category/protocol/IMP relationships.
- [ ] **Add type propagation and casts.** Propagate types bidirectionally through assignments, calls, returns, pointer arithmetic, and memory access. Mark conflicts and avoid silently coercing incompatible evidence.
- [ ] **Add analyst overrides.** Project-local function overrides now persist an analyst name, signature hypothesis, confidence, and note, display them as annotations without altering decoded evidence, and retain up to ten per-function revisions for undo. Variable/type edits, switch marking, split/merge operations, and cross-function undo/redo remain.

## P2 — Broaden analysis coverage

- [ ] **Recover data references and strings.** Improve pointer/string cross-references, constant-address resolution, Objective-C constant strings, CFString/CFData patterns, and global variable naming.
- [ ] **Recognize common library idioms.** Exact prototypes now identify memory allocation/copy/clear/compare, string operations, Objective-C retain/release, and libdispatch calls in pseudocode. Data-flow idiom recognition for bounds checks, tagged pointers, dispatch blocks, and Foundation/CoreFoundation patterns remains.
- [ ] **Recover switch tables and indirect control flow.** The worker now recovers up to 32 executable-aligned targets for indexed 64-bit pointer tables and table-relative signed-offset tables when ADR/ADRP plus ADD provenance and the BR data path match. The pseudocode renders those entries as a candidate switch on the table index, with address-bearing case targets and an unresolved default. Case-range proof, index normalization, other encodings, and Objective-C/C++ vtable recovery remain.
- [ ] **Add another architecture through the IR.** Prioritize x86-64 Mach-O. Implement its lifter, ABI model, and calling-convention tests against the same function IR; do not claim decompilation coverage for architectures that only receive structural parsing.
- [ ] **Handle stripped and optimized code better.** Use unwind metadata, thunk/tail-call recognition, prologue evidence, cross-references, and call graph constraints to discover functions and distinguish cold fragments.
- [ ] **Add function and call graphs.** Show callers/callees, Objective-C dispatch possibilities, unresolved indirect calls, and confidence. Support graph navigation and analyst annotations.

## P3 — Make results reviewable and scalable

- [ ] **Add per-function analysis controls.** The Binary Workspace now filters CFG blocks to the selected function and lets users navigate from block/edge records to instruction addresses alongside assembly, lifted statements, IR, and pseudocode. Per-function reanalysis, analysis bounds, and simplification controls remain.
- [ ] **Expose uncertainty and alternatives.** Let analysts inspect competing type, target, function-boundary, and control-flow hypotheses with the evidence that supports each.
- [x] **Add decompilation quality corpus.** Public-domain C, Objective-C, C++, and Objective-C++ fixtures compile at `-O0`/`-O2` with stripped and unstripped variants. The macOS runner scores function, CFG, IR, pseudocode, validated Objective-C method, selector message-send, address-bearing parameter-name use, pseudocode-to-IR source-address mapping, recovered parameter names, expressions, resolved call targets, and type evidence without exact source-text matching. The same quality gates run in macOS CI.
- [ ] **Add resource and cancellation controls.** Bound work per function and project, expose progress, and allow cancellation without discarding completed analysis.
- [ ] **Export standard artifacts.** Add function signatures, types, call graphs, and annotations to JSON and interoperable formats where practical.

## Suggested implementation order

The [master's active sequence and immediate queue](CHIMERA_COMPLETION_ROADMAP.md#active-priority-aarch64-pseudocode-and-source-reconstruction) are authoritative. Reuse the existing parser/IR/native evidence work; do not restart these foundations.

1. Fix correctness and naming gaps in current AArch64 pseudocode, including frame updates, unknown effects and reserved-encoding fallbacks (C00/C01/early C02–C06).
2. Canonicalize register/flags/vector and memory SSA, stack frames, aliases and lifetimes; remove text-reparsed effect/name decisions (C02/C03).
3. Extend ABI/call recovery and Apple-native image/name/declaration/type/layout joins for the supported slice (C00N/C04–C06).
4. Recover source variables and typed expressions, then nested conditions/loops/switches with CFG/effect checks (C05/C07/C08).
5. Export recompilable C17/Objective-C; qualify original/IR/generated behavior and near-original fidelity separately (C01/C09/C10/first C12 gate).
6. Complete integrated evidence review/corrections, then expand languages/ISAs/formats and remaining product requirements (C11–C16).

Source mapping, evidence graphs, resource limits, cancellation, persistence, native declarations and validation accompany every phase. A small end-to-end export/differential slice starts early; none waits for complete ISA or general type coverage. The master list supplies detailed dependencies and acceptance evidence.
